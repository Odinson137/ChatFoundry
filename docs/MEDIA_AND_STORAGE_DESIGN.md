# Медиа и файловое хранилище — решения

## 1. Тип медиа: ручной выбор vs авто при выборе файла

- **Ручной выбор (enum Image/Video/File/Audio)**  
  Плюсы: полный контроль; при источнике «Ссылка» тип обязателен. Минусы: лишний шаг при загрузке файла.

- **Авто при выборе файла**  
  По MIME/расширению выставляем тип (image/* → Image, video/* → Video и т.д.). Плюсы: удобство. Минусы: для «Ссылка» тип всё равно нужен; возможны неточности (например .mov как File).

**Решение:** комбинированный подход: при выборе/загрузке файла тип подставляется автоматически; пользователь может вручную изменить тип; при режиме «Ссылка» тип выбирается вручную.

## 2. Файловое хранилище: стоимость и удобство

| Хранилище      | Хранение (порядок)   | Запросы / egress        | Удобство в .NET |
|----------------|----------------------|-------------------------|------------------|
| **GCS**        | ~$0.02–0.026/GB      | Class A дороже          | Google.Cloud.Storage.V1, хорошо |
| **AWS S3**     | ~$0.023/GB           | Дешевле                 | AWSSDK.S3, presigned URL из коробки |
| **Azure Blob** | ~$0.018/GB (LRS)     | Средне                  | Удобно в Azure |
| **MinIO**      | Self-hosted, бесплатно | S3-совместимый         | Тот же S3 API |

Для нашего кейса выбран **GCS** (как в Pilot); при необходимости можно ввести абстракцию под S3-совместимый API (MinIO/S3).

## 3. Прямая загрузка из фронта в storage (без прокси через бэкенд)

**Да, так можно.** Схема:

1. Фронт запрашивает у бэкенда «URL для загрузки» (presigned/signed PUT URL в GCS).
2. Бэкенд генерирует ключ (путь в бакете, например `chatfoundry/{tenantId}/{workflowId}/{guid}.{ext}`), создаёт signed URL для PUT, возвращает его и ключ фронту.
3. Фронт загружает файл **напрямую в GCS** по этому URL.
4. Фронт отправляет бэкенду только **ключ** (и при желании метаданные) — например «файл залит, ключ = ...».

**FileService без БД:** ключ = путь объекта в бакете. Эндпоинт `GET /files/{key}/url` по ключу возвращает публичный URL или подписанный URL для скачивания — без хранения метаданных в БД. Список «уже загруженных» файлов для выбора в блоке Медиа можно вести в БД (только каталог: ключ, имя, размер, дата) — тогда БД только для каталога, не для содержимого.

В текущей реализации: поддержка и «классической» загрузки через бэкенд (multipart в FileService), и режима «получить signed URL → загрузить с фронта → сообщить ключ».
